# Artemis Labs Web Dashboard

Three-phase command dashboard: **Login → Device Selection → Device Control**.

## Run

```bash
cd dashboard_web
python3 -m pip install --user --break-system-packages fastapi uvicorn jinja2   # once
python3 main.py
```

- Dashboard: http://localhost:5000
- Admin password: auto-generated on first run, saved to `~/.config/artemis/admin_password.txt`
  (or set env `ARTEMIS_ADMIN_PASSWORD`)
- Paired devices: `~/.config/artemis/devices.json`

## Three Phases

1. **Login** (`/`) — single-admin clearance gate. Session cookie, 1h expiry.
2. **Device selection** (`/` after auth) — fleet grid, search filter, pair modal
   (host + 6-digit code read off the phone screen), manage/forget actions.
3. **Device control** (`/dashboard/<host>:<port>`) — live status cards,
   GPS location, camera sensor list + capture, mic toggle, device info.

## Architecture

- `main.py` — entry point (uvicorn)
- `server/config.py` — paths, admin password, ports
- `server/auth.py` — session management
- `server/device_client.py` — raw-socket HTTP client to phone's Artemis server
- `server/device_manager.py` — paired-device registry (JSON persisted)
- `server/__init__.py` — FastAPI app + routes
- `templates/` — Jinja2 pages (UI generated by Stitch MCP, design system
  "Artemis Labs Brand Identity", see `DESIGN.md`)
- `static/` — vanilla JS + minimal CSS

## Security notes

- Session cookie is HttpOnly; all device routes require login.
- Pairing code is NEVER exposed via any network endpoint — it is read off
  the phone screen and entered manually in the pair modal.
- Backend proxies to phones over cleartext HTTP on LAN/Tailscale (no TLS yet).
